# Refresh do3 support container images

Issue: [#391](https://github.com/willjasen/rawrarr/issues/391)

## Scope and compatibility

Refresh only third-party support images declared in the repository's internal and public do3 support-image Compose overlays. The updater preserves each deployment's active Compose files and service settings, pulls one service at a time, and recreates only that service. It excludes Rawrarr application images and local custom images. PostgreSQL stays on major version 17; no database schema or application protocol migration is needed. PostgreSQL data, Tailscale state, analytics state, secrets, and all other volumes remain attached.

Mutable Caddy and Tailscale tags are refreshed from their configured `2-alpine` and `stable` tags. Version- or digest-pinned images are checked against the configured image reference but are not silently moved to a different release. Changing those pins requires a separately reviewed version update. Each changed service's previous image is retained under a `rawrarr:rollback-support-*` tag. The updater restores that image if the recreated service fails readiness or the internal health/Serve verification.

## Published-source procedure

1. Use the full SHA of a published GitHub `main` commit that contains the updater and both support-image overlays. Download its authenticated source archive to a new directory outside `/shared`, verify the archive digest, and extract it without overwriting an existing build directory.
2. On do3, confirm Docker reports `linux/amd64`, inspect free disk space, and confirm the internal and public per-service deployment markers are clear. Never prune images, volumes, BuildKit cache, or user files to make room.
3. Run `python3 <source-root>/deploy/do3/update_support_images.py --source-root <source-root>`. To target only one environment, add `--project rawrarr-internal-do3` or `--project rawrarr-roarlay-prod`.
4. The updater checks the active Compose project, service, and resolved image against the repository overlay. It passes the project's protected `secrets/analytics.env` to Compose when present. For internal Compose interpolation it uses the image reference from the running roarlay container without changing roarlay; for public CrowdSec Compose files it derives the source SHA and bouncer secret-file path from the active Compose files and existing project secret. It waits for the relevant per-service marker, pulls only the selected service, and skips recreation if the image ID has not changed. For a changed image, it saves a rollback tag and runs only `docker compose up -d --no-deps --pull never <service>`. Locks remain held through service readiness and route verification.
5. Confirm the internal Tailscale Serve route still maps `/` on `rawrarr.risk-mermaid.ts.net:443` to `http://127.0.0.1:8080`, and that both local roarlay `/health` endpoints return success. The updater also checks the internal HTTPS health route. From do3, Cloudflare may return HTTP 403 for `https://roarlay.rawrarr.net/health`; this is reported as a warning when the public local health check succeeds and does not trigger rollback. Inspect the final service image IDs, Compose project labels, and health states.

If an update fails, the updater restores the prior image for that service and verifies it is running before releasing its marker. If rollback or route verification also fails, stop further changes, preserve both images and project state, and recover that service under its marker. Do not restart dependencies or delete volumes. An older image may be insufficient as rollback if a later release changes a persistent data format; this procedure limits PostgreSQL to its configured major version and does not change application schemas.

## Execution record

The updater and its follow-up fixes were merged in PRs [#393](https://github.com/willjasen/rawrarr/pull/393), [#396](https://github.com/willjasen/rawrarr/pull/396), and [#398](https://github.com/willjasen/rawrarr/pull/398). The refresh used published `main` SHA `70130fdf2a23f5bbde3bfcc92ccfb7f9ad1e8b2a`; its verified source archive SHA-256 was `39b7683112b4d82067a30c582032d854d81cc1549515f1ea3dbebf18d47f968a`.

The repo updater refreshed internal PostgreSQL, Tailscale, analytics Caddy, and Umami PostgreSQL, plus public PostgreSQL, Tailscale, Caddy, and Umami PostgreSQL. The configured cloudflared digest, CrowdSec `v1.8.2`, Headscale `0.29.5`, and Umami `3.4.1` images were already current and were not recreated. Each changed service retained its prior image under a `rawrarr:rollback-support-*` tag. The updater's first attempt stopped after internal PostgreSQL and Tailscale because the protected analytics environment was not exported; resuming with that project's protected environment completed the internal targets. Its next attempt stopped at the public CrowdSec Compose validation because that deployment also requires its active published-source and bouncer-secret paths; resuming with the public environment completed all targets.

The refresher's final command exited nonzero after completing its updates because the public-edge warning path passed `check=False` to a helper that did not yet accept that option. Independent verification then confirmed all 12 target containers are running with the expected Compose project/service labels; PostgreSQL and public Caddy health checks are healthy. Internal/public local roarlay health returned HTTP 200, internal HTTPS health returned 200, and Tailscale Serve still maps `/` to `http://127.0.0.1:8080`. The public edge returned HTTP 403 from do3, the expected Cloudflare restriction. Compose's orphan warnings were informational; the updater did not remove or recreate orphan services. While this work was in progress, the scheduled coordinator updater independently applied the same published Rawrarr image to both roarlay containers; the support-image updater did not target those app containers.

A follow-up updater correction is being prepared to pass protected per-project environment files, derive public CrowdSec inputs from the active Compose files, and correctly handle the expected public-edge warning response.
