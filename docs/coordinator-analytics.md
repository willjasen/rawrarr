# Coordinator analytics

Rawrarr can optionally send one anonymous page-view event from the coordinator landing/workspace page to a self-hosted Umami instance. Analytics is off unless both `RAWARR_ANALYTICS_UPSTREAM` and `RAWARR_ANALYTICS_SITE_ID` are configured. It never tracks subscriber pages, APIs, health checks, node relays, or user actions.

The integration disables Umami's automatic tracking and submits only a fixed `/coordinator` page label and title. It does not send the browser URL, query string, referrer, account/device/node identifiers, library data, or event properties. The site ID must contain only letters, digits, hyphens, or underscores. The server proxy only allows `http://umami:3000` and the Umami tracker and event routes. Invalid or incomplete settings leave tracking disabled. The coordinator forwards the client IP and browser user-agent to Umami so it can calculate visitor metrics; Umami uses these to derive anonymous session metrics. Self-hosting controls where this data is stored but does not mean no visitor data is processed. Review Umami's [metric definitions](https://docs.umami.is/docs/metric-definitions).

## Deployment

Merge `docker-compose.analytics.yml` into the existing coordinator Compose project on each host. Set `RAWARR_ANALYTICS_NETWORK` to that coordinator project's private Docker network (the current do3 networks are `rawrarr-internal-do3-control` and `rawrarr-roarlay-prod-control`). Umami joins that private network, while its PostgreSQL port is not published. The Umami web service binds only to host loopback port 7300 for administration. The public coordinator proxies only the tracker and event endpoints at its existing HTTPS origin under `/analytics`. The internal do3 coordinator uses the additional `deploy/do3/docker-compose.analytics-dashboard-internal.yml` Caddy front on its Tailscale Serve route; internal Umami uses `BASE_PATH=/analytics`, so the dashboard and tracker routes share that path. Use a separate Umami website/site ID and database volume for each environment. The analytics database is not Rawrarr PostgreSQL and contains no Rawrarr application records.

The internal dashboard is available at `https://rawrarr.risk-mermaid.ts.net/analytics` through the tailnet-only Caddy route, with Umami login still required. The public coordinator does not expose its dashboard. Do not expose PostgreSQL. Set `RAWARR_ANALYTICS_UPSTREAM=http://umami:3000` and `RAWARR_ANALYTICS_SITE_ID` to that environment's Umami website ID. Leave either empty to disable tracking.

Create a strong independent DB password, an application secret, and a 64-character hex 2FA encryption key in the host's protected environment file. Keep that file out of Git and `/shared`. Self-hosted Umami retains analytics records indefinitely; no expiration job is configured. Back up the Umami database separately and test restore before upgrades. The Compose image is pinned to Umami `3.4.1`; review upstream security releases before changing the tag. Upgrade the analytics service independently from Rawrarr.

For both internal and public coordinator deployment files, pass `RAWARR_ANALYTICS_UPSTREAM` and `RAWARR_ANALYTICS_SITE_ID` to roarlay. Use separate site IDs and database volumes so internal testing traffic does not mix with public usage. Start `umami-postgres` and `umami` first, create an administrator, enable 2FA, create the environment-specific website, then enable the coordinator settings. Verify the browser loads `/analytics/script.js`, posts only the fixed `/coordinator` pageview to `/analytics/api/send`, and the event appears in that environment's dashboard. To roll back, clear either coordinator setting and recreate roarlay; the Umami service and its volume can remain running. Deleting the Umami volume permanently deletes analytics history.

This adds a separate analytics data domain but changes no Rawrarr persistent data, schema, node protocol, or synchronized `/shared` content. Existing deployments adopt it by adding the analytics Compose overlay and the two optional coordinator environment variables; no migration is required.
