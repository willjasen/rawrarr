# Deploy the Mac mini storage node

## Objective

Connect a Mac mini storage node and the seeded MacBook metadata node to the already provisioned, healthy coordinator. Use containerized Tailscale and Syncthing, and require explicit owner approval for the joining node. The coordinator must receive no age identity, media, or node-local application data.

## Initial state

- The established MacBook Rawrarr coordinator and seeded metadata participant were healthy; the MacBook Tailscale container was authenticated and Serve exposed the transitional metadata UI on HTTPS 443.
- The Mac mini had OrbStack and a running, authenticated `rawrarr-mini-tailscale` container. Its protected Tailscale state persists under `~/Library/Application Support/rawrarr/tailscale/mini`.
- `/Volumes/silo/Media/data` existed with about 656 GiB free on the mounted volume. The Mini had no Rawrarr shared-data folder or Rawrarr app container.
- The MacBook's Rawrarr Syncthing container had the `rawrarr-shared` folder but no peer and listened on its container loopback. A separate host Syncthing process also existed; it is outside this task and was left untouched.
- The owner requested a browser approval flow on an already signed-in node. Age identities must remain node-local and outside coordinator requests and Syncthing.

## Actions and verification

- Added coordinator-side pending enrollment and explicit approval through an already signed-in metadata/storage node. New nodes generate a random token in local `/data`; enrollment payloads contain only node ID, role, display name, WebAuthn origin/RP ID, request ID, and a one-way token verifier. Strict deserialization rejects extra fields including `ageIdentity`. Approval requests expire after 15 minutes. The token never enters `/shared`.
- Added the signed-in Devices UI to list pending requests and require an explicit **Approve node** click. It does not auto-approve. Local metadata UI and coordinator containers were rebuilt in the existing `rawrarr-local` project without deleting volumes; both containers and PostgreSQL are healthy, `http://127.0.0.1:7297/health` returns 200, and the existing tailnet UI health route returns 200.
- MacBook Tailscale Serve retains HTTPS 443 to the metadata UI and adds tailnet-only TCP 22000 forwarding to the Rawrarr Syncthing container. The Syncthing container now listens on its container interface. The MacBook UI and coordinator proxy use a shared trusted Docker network. No host Syncthing configuration or process was changed.
- Started `rawrarr-mini-syncthing` as a Docker container in the existing Mini `rawrarr-local_default` network. It has a persistent Syncthing volume and `/shared` bind only, and uses `ALL_PROXY=socks5://tailscale:1055` with fallback disabled. The shared folder transfer completed and the encrypted `config.aged` plus public `age-recipient` are present. A disposable container test confirmed it reaches the MacBook through the Mini Tailscale sidecar's SOCKS5 route.
- Paired the Mini Syncthing container with the MacBook Rawrarr Syncthing container for only the `rawrarr-shared` folder. The peer connection is established through Tailscale Serve port 22000. The MacBook source contains about 312 MB (2,526 files, 17 directories, including `config.aged` and the public `age-recipient`). The transfer later completed and both files were verified on the Mini before storage startup.
- Added a restricted enrollment pass-through on the metadata node for only `POST /api/nodes/enroll` and `/api/nodes/enroll/status`. It forwards the joining node's 64-character bearer token and bounded JSON body to the coordinator, without adding metadata-node credentials or browser cookies. Coordinator request deserialization rejects unknown fields, including `ageIdentity`. Regression tests cover the allowed routes, token shape, payload field set, and local proxy hostname.
- Added coordinator account ownership to pending enrollments and registered nodes. The joining node sends no user ID; the healthy single-owner coordinator assigns the request to its sole existing account and exposes its display name on the signed-in Devices approval card. Requests fail closed if the coordinator has no owner or multiple owners. The seeded MacBook metadata node remains pre-approved and is not re-enrolled. A future multi-account setup needs owner-issued invitations.
- Rebuilt the MacBook coordinator and metadata service using the existing `rawrarr-local` Compose project. The account-ownership migration 0004 applied; it assigned the seeded `macbook-metadata` node and the existing pending mini request to the sole coordinator account. Both local health routes and the tailnet health route return HTTP 200. A protected PostgreSQL custom-format backup was created at `/tmp/rawrarr-before-node-owner-20261018.dump` before migration. Rebuilt and restarted the Mini storage image while retaining its existing `rawrarr-local_rawrarr-data` volume. The coordinator database confirms the current `mac-mini-storage` / `storage` request for `Mac mini` is unexpired and assigned to the existing account.
- Mini storage mounts only its local `/data` volume, `/Volumes/silo/Media/data` read-only at `/media`, and the Syncthing folder at `/shared`. Its generated bearer token is stored only at `/data/node-token`; no age identity path or identity file is mounted or transmitted. The container waits for approval before opening its web listener, so its host `/health` is expected to remain unavailable until approval completes.
- Focused approval-UI and lowercase-brand Node tests passed before the ownership UI change; rerun them after deployment. The isolated full suite previously had environment/flaky Node failures and an age ciphertext test failure. Role-deployment integration and live post-approval registration were not run. `git diff --check` passed; host rustfmt could not start because its LLVM installation is missing `libz3.5.1.dylib`.
